# Blueprint: harness capabilities

`SKILL.md` names tools by their Claude Code spelling. On a Codex driver, read this table before Phase 0 and substitute per it rather than skipping a step. The roles (driver, foreign reviewer, same-family leg) are defined in `SKILL.md` under Harness capabilities.

| Capability | Claude Code driver | Codex driver |
|---|---|---|
| Foreign reviewer (plan audits, post-impl fix loop, cross-arc pass) | `/codex` → `run-codex.sh` / `resume-codex.sh` on the Phase 0 `codex_model` (`gpt-6.2-sol` or `gpt-6.2-astra`, passed as `run-codex.sh`'s fifth argument, since its own default is Astra; resumes stay on the session's model). Gemini, on either driver: `run-agy.sh` / `resume-agy.sh` on the Phase 0 `gemini_model`, as `SKILL.md`'s Gemini leg says; the call passes this session's own permission gate for a Bash call | `/claude` → `run-claude.sh` / `resume-claude.sh` on the Phase 0 `claude_model` (`opus` = Opus 5.5 or `fable` = Fable 5.1, passed as the scripts' fifth argument, since their own default is `fable`). Must run **escalated** — Claude Code needs the network and writes `~/.claude`, which the Codex sandbox blocks. Use access the session already has; when it lacks it and no approval can be obtained (`approval_policy = never`, no human), the foreign review is **blocked**: log it in lessons and hold the gate — never substitute a same-family pass for it. Gemini: the same scripts and commands as `SKILL.md`'s Gemini leg (also linked under `~/.agents/skills/gemini/scripts/`). They must run **escalated** too, since Gemini reaches the network and runs outside the sandbox. The escalation request says in one line what it starts: Gemini on the Antigravity CLI reviews `<worktree>` from `<prompt-file>`; it sends repository content to Google, holds the paid Gemini key in its environment, and runs unsandboxed as this user, so it can read and write anywhere this user can. A stub call says it is a stub call. Starting the Gemini leg hands Gemini everything this user can do on this machine. Never give it a task this session was denied, or one its own settings would block (no permission laundering); a denial goes to the owner. A refused escalation is `GEMINI: unavailable (blocked)`, which you print and log in lessons, and which goes to the owner. Unlike a blocked Claude review, it holds nothing: the gate goes on without Gemini |
| Same-family leg | `Agent` tool, `subagent_type: 'Plan'`, `model:` the Phase 0 `claude_model` (`'opus'` or `'fable'`) | Codex subagent (built-in `default`, or a `~/.codex/agents/*.toml` agent) on the Phase 0 `codex_model` |
| Recon explorers (0.4) | `Explore` subagents, `model: 'sonnet'` (the newest Sonnet) | built-in `explorer` subagent on a cheap GPT-5.6 tier (`terra` / `luna`) |
| Worktree homing (0.75) | `EnterWorktree` (this skill's instruction is its standing authorization) | `agent-worktree new <slug> --no-start`, then work from the printed path — same layout, same manifest row |
| Post-merge teardown | `ExitWorktree` with `action: "keep"` when this session entered through `EnterWorktree` (this skill's instruction is the request that tool requires), then `agent-worktree done <slug> --merged` | `agent-worktree done <slug> --merged` — it finds the worktree through the manifest, so the cwd does not matter |
| Clarifying questions (0) | `AskUserQuestion` | Ask in prose in the TUI. In `codex exec` there is no user: record each question as an **Ask** in Assumptions with your working assumption, and let the approval gate block on it |
| Task list | `TaskCreate` / `TaskUpdate` | The printed step checklist (see Status visibility), printed only when a step changes state |
| ELI5 companion | `Artifact` tool (primary) | `eli5.html` file mode + `BLUEPRINT_VIEW_CMD` — the preflight already falls back when the Artifact tool is absent |
| Opt-in diff review (`code_review`) | `/code-review <level> --fix` | `codex review --base <arc-base>` (committed changes included) for findings; apply them by hand, commit separately |
| Execution seeds | `/goal` + `/loop 15m` | `/goal` exists on Codex; `/loop` does not — emit only the `/goal` seed, and fold the `/loop` template's dispositional rules (never idle, consult the foreign reviewer when stuck, hard limits) into plan.md's Post-implementation section so the driving session reads them from there |
| Foreign legs that "spawn researchers" or "persist reports" (`deep`, `mega-deep`) | The `Agent` fable leg does both natively | Neither foreign leg — `/codex` in its read-only sandbox, `/claude` with Read/Grep/Glob only — can spawn agents or write files. The **driver** runs the research (its own subagents), passes the findings in the prompt, and persists whatever the foreign leg returns as the artifact. Gemini, on either driver, reads the worktree in place with commands, but it is told not to write files and its edit tools are denied, so the driver persists its report too |
